The minimized search-tracks.json fixture follows the field shape documented by Deezer's public API examples and the public fields specified for /search. Its IDs and image/preview URLs are illustrative test values (the .example preview URL is intentionally non-playable); it is not represented as a captured live response. The Android CI workflow makes one live search call, prints the first result's title, preview host, and field names, and is configured continue-on-error so the runtime response can be checked without making CI depend on Deezer availability.
